# 아이디어 심층 검증 (자기 반박 루프)

이미 idea-check로 1차 통과한 아이디어 1개를 대상으로, 사용자가 직접 캐물었을 때 나올 법한 수준의 반박을 스스로 던지고, 막히면 고쳐서 다시 검증하는 과정을 사용자 개입 없이 반복한다.

## 핵심 규칙

- **역할은 두 개, 실행은 한 번의 흐름 안에서 번갈아가며 한다.** 실제로 두 개의 별도 세션을 띄워 대화시키는 게 아니라, 한 번의 진행 안에서 "검증자"와 "개선자" 관점을 순서대로 취한다.
- **최대 6라운드.** 라운드 상한이 없으면 스스로와 끝없이 논쟁하며 시간과 비용만 쓰고 결론이 안 난다. 6라운드 안에 통과하지 못하면 상한선에서 멈추고 결과를 솔직히 보고한다.
- **라운드가 늘어난 만큼 매 라운드 같은 걸 반복 공격하지 않는다.** 이전 라운드에서 이미 확인한 지점은 다시 묻지 않고, 아직 안 건드린 기준으로 넘어간다 (수요 → 경쟁 → 마케팅 → 기술구현 → 비용 → 시간, 순서로 훑되 이미 통과한 기준은 건너뛴다).
- **매 라운드 근거는 이번 아이디어 전용으로 새로 검색한다.** 이전 라운드, 이전 세션, 혹은 다른 아이디어를 검증하며 찾았던 근거를 가져다 쓰지 않는다. 대상·가격대·업종이 조금이라도 다르면 다른 검색이 필요한 별개의 사실이다.
- **"결함 없음"은 결함을 찾아보고 나서 내리는 결론이지, 안 찾아봐서 나오는 결론이 아니다.** 매 라운드, 통과 처리하기 전에 반드시 "이 가격대·이 타겟에 이미 하는 저가/무료 대안이 있는지"를 최소 1회는 직접 검색해서 확인한다. 비싼 경쟁자만 확인하고 저가 경쟁자를 안 찾아본 채 통과시키지 않는다.
- **무료·기존 습관 대안도 경쟁자로 취급한다.** 타겟 고객이 이미 쓰고 있는 공짜 대체 수단(예: 이미 쓰는 카카오톡 채널 무료 자동응답)이 있으면, 유료 전환 의지가 없을 수 있다는 뜻이므로 이것도 수요 쪽 결함 후보로 검색해서 확인한다.
- **업종에 규제·인허가·개인정보 이슈가 있으면 반드시 검색해서 짚는다.** 의료·금융·법률처럼 규제가 있는 업종이면 "이 부분을 3자 서비스에 맡기는 게 법적으로 문제없는지"를 최소 한 라운드에서 검색으로 확인한다.
- **매 라운드 근거는 웹 검색으로.** 추측으로 반박하거나 추측으로 개선하지 않는다.
- **검증자는 진짜로 탈락시키려는 태도로 임한다.** 아이디어를 살리는 쪽으로 편들지 않는다. 사용자가 직접 캐물을 때처럼 가장 아픈 질문부터 한다 (돈 낼 사람이 실제로 있는가, 이미 큰 회사가 하고 있지 않은가, 이 사람이 정말 이걸 필요로 하는가, 더 싸거나 공짜인 대안으로 충분하지 않은가).

## 진행 순서

**0단계 — 입력**
검증할 아이디어 1개와, 있다면 idea-check의 1차 검증 결과(6기준 표)를 가져온다.

**1라운드부터 반복 (최대 6회, 6가지 검증 기준을 한 라운드에 하나씩 순서대로 훑는 걸 기본으로 한다):**

1. **검증자 역할**
   - 이번 라운드에서 가장 약해 보이는 지점 1~2개를 고른다 (수요, 경쟁, 마케팅, 기술 구현, 비용, 시간 중).
   - 그 지점에 대해 사용자라면 물어봤을 법한 날카로운 질문을 스스로 던진다. 예: "정말 이 문제로 돈을 낸 사례가 있는가?", "무료 대안으로 충분한 사람이 대부분 아닌가?"
   - 웹 검색으로 근거를 찾아 답한다. 근거가 나쁘면(수요 없음, 이미 포화, 답 없음) **치명적 결함**으로 표시한다.
   - 치명적 결함이 하나도 없으면 → 이번 아이디어는 **통과**로 확정하고 루프를 끝낸다.

2. **개선자 역할** (치명적 결함이 나온 경우에만)
   - 그 결함 하나만 정확히 겨냥해서 아이디어를 수정한다. 전체를 갈아엎지 않는다 (예: 타겟층을 좁힌다 / 가격 모델을 바꾼다 / 기능 범위를 줄인다 / 채널을 바꾼다).
   - 수정 전/후를 한 줄씩 비교해서 무엇을, 왜 바꿨는지 적는다.
   - 수정판을 들고 다음 라운드의 검증자에게 넘긴다.

3. **라운드 종료 조건 확인**
   - 통과 → 종료.
   - 6라운드를 다 썼는데도 결함이 남음 → 종료하고, 마지막 상태를 솔직히 보고한다 (이 아이디어는 이 결함 때문에 이 형태로는 어렵다는 점을 숨기지 않는다).

## 출력 형식

1. **최종 결론** — 통과했는지, 몇 라운드 만에 통과했는지, 혹은 6라운드 안에 못 넘은 결함이 무엇인지 한 줄로.
2. **라운드별 요약** — 라운드마다: 검증자가 던진 질문 → 찾은 근거 → 결함 여부 → (있었다면) 개선자가 어떻게 고쳤는지. 표나 짧은 블록으로, 라운드당 3~4줄 이내.
3. **최종 버전 아이디어** — 원래 아이디어와 최종 수정판을 나란히 비교 (바뀐 부분이 없으면 "원안 그대로 통과"라고 명시).
4. **다음 한 걸음** — 지금 당장 해볼 수 있는 가장 작은 검증 행동 하나.

## 주의

- 통과시키고 싶어서 근거를 관대하게 해석하지 않는다. idea-check보다 오히려 더 깐깐해야 한다.
- 매 라운드 결함을 못 찾았다고 억지로 지어내지 않는다. 다만 "못 찾았다"는 진짜로 저가·무료 대안까지 찾아본 뒤에 하는 말이어야 한다. 안 찾아보고 통과 처리하는 건 검증이 아니라 방치다.
- 6라운드를 다 쓰고도 안 되면 "그래도 좋은 아이디어"라고 포장하지 않는다. 안 되면 안 된다고 말한다.
